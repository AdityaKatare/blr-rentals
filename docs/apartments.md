# Apartments and societies

Listings carry a free-text `society_name` from the portals. 8,261 of 14,945 active listings have one, across
roughly 2,680 distinct names. There is no separate societies table: an apartment is whatever group of listings
shares a slug.

## The slug

Migration `0002_society_slug.sql` adds a stored generated column:

```sql
society_slug = nullif(btrim(regexp_replace(lower(btrim(society_name)), '[^a-z0-9]+', '-', 'g'), '-'), '')
```

`societySlug()` in `packages/core/src/society.ts` is the TypeScript twin of that expression, and
`packages/core/test/society.test.ts` pins the two together. Change one and you must change the other, or the
search box and the apartment pages will disagree.

The slug folds spelling variants that differ only in case or punctuation, which is most of the duplication in the
data: `SNN Clermont` and `Snn Clermont`, `Assetz Here and Now` and `Assetz Here And Now`, `Valmark Aastha,` and
`Valmark Aastha`. Around 30 name pairs merge this way.

It does **not** fold genuinely different names for the same complex. `L&T Raintree Boulevard` and
`L And T Raintree Boulevard Phase 2` stay separate pages. This is deliberate: guessing that two names are the
same place needs the location, not the string, and grouping the wrong towers together is worse than showing two
pages. The search box covers it anyway, because a society query also matches on `society_name ILIKE '%text%'`.

## Where each piece lives

| Piece | Location |
|---|---|
| Apartment index and name search | `/societies`, busiest 60, name search over the trigram index |
| Apartment page | `/societies/<slug>`, every live unit, no radius |
| Queries | `packages/db/src/queries/societies.ts` |
| Name suggestions | `societyOptions()`, busiest 300 city-wide, cached for ten minutes in `apps/web/server/societies.ts` |
| Way in from a result | the apartment name in each card heading links to its page |
| Metro distance | nearest open station to the apartment's own centre, both on the index rows and its page |

A name shorter than four characters is treated as junk and kept out of the index and the suggestions, because the
data holds a handful of entries like `SB` and `no`. Such a listing still reaches its own page by slug.

Unit counts group duplicates across sources the same way search does, with `count(DISTINCT COALESCE(property_id, id))`,
so a flat listed on both portals counts once.

## Distance to the metro

Each apartment reports the nearest open Namma Metro station, measured in a straight line from the centre of the
listings that carry a precise location. Listings placed only at their locality centre are left out of that centre,
for the same reason they are left out of the per-listing metro filter: the locality centroid is not where the
towers are.

Nothing is reported past 3 km, which is `NEAREST_METRO_MAX_M` shared with the listing cards. About a third of the
busiest 60 apartments have an open station inside that range today, because several of the largest complexes sit
in the north and east where the lines are still under construction. Upcoming stations are seeded but never used
here, so the figure never implies a station you cannot ride.

## Why apartment search is not a filter on the search page

It was, briefly, and it was wrong. The rent search is anchored on a centre and a radius, so an apartment name
combined with an area can only return something when the apartment happens to sit inside that circle. Searching
Peenya for Prestige Shantiniketan returned nothing, because that complex is in Whitefield, and a zero-result page
is a bad way to learn that two filters contradict each other.

Looking inside one apartment is a different question from looking around one place, so it has its own page and
its own search box, and neither knows about a radius. An apartment page offers a link back into a radius search
around its own coordinates for anyone who wants the surrounding area.

## Refreshing

Nothing to refresh. The slug is generated by Postgres on write, so a scrape run keeps it current and the apartment
pages follow automatically.
